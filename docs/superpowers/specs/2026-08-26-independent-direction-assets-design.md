# 四向八向独立方向资产修复设计

## 状态

本设计已于 2026-08-26 由用户确认。它补充并覆盖
`2026-08-25-direction-sheet-candidate.md` 中四向预览沿用 3×3 布局的约定：四向改为
2×2 四宫格，八向继续使用中心留空的 3×3 九宫格。

## 问题

当前链路虽然会为不同方向创建独立生成任务，但仍有三处会让最终结果表现为“一张错误的
四视图图片”：

1. 角色描述会原样进入图片 Provider。描述中出现“四向视图”“朝上、朝下、朝左、朝右”
   等多视图构图要求时，Provider 可能在单次调用中生成一张带多个角色的拼图。
2. 方向提示只描述屏幕空间的上、下、左、右，没有明确角色在固定投影下应展示的身体表面，
   容易把北向理解成俯拍，或让多个方向都退化为同一个侧面。
3. Quick Start 与 Workflow Editor 在方向集合确认后只渲染东向母版，丢失了已持久化的其余
   方向展示。

## 产品合同

### 独立资产

- 单向：一张真实东向图片；旧资产的西向镜像兼容保持不变。
- 四向：东、西、北、南各有一个独立生成任务、独立媒体 URL 和独立持久化字段。
- 八向：东、西、北、南、东北、西北、东南、西南各有一个独立生成任务、独立媒体 URL
  和独立持久化字段。
- 一张图片只能包含一个角色实例和一个方向。方向拼图、转面表、精灵表不能作为某个方向的
  生成结果。
- 不裁切 Provider 返回的方向拼图，也不从其中派生方向资产；不使用镜像补齐四向或八向。

### 展示布局

- 四向使用 2×2 四宫格。上排为北、南，下排为西、东；每格带方向标签。布局顺序只负责
  展示，不改变方向与媒体 URL 的映射。
- 八向使用 3×3 九宫格：

  ```text
  西北  北  东北
  西   空   东
  西南  南  东南
  ```

- 九宫格中心始终为空，不创建占位媒体，也不参与确认、持久化或导出。
- 单向继续使用单图预览，不展示空宫格。
- 宫格只是多个独立 `<img>` 的组合视图，不生成新的拼图文件，不上传新的合成媒体 URL。

## 生成流程

1. Quick Start 或 Workflow Editor 先按现有流程生成三张单方向身份母版候选。
2. 用户确认其中一张后，将它作为唯一身份锚点。
3. 编排器读取项目的单向、四向或八向规格，为尚未完成的每个真实方向各提交一个图片任务。
4. 每个方向任务都携带同一身份锚点，但使用自己的方向枚举和方向提示。
5. 每个成功结果分别写入 `selectedImages[direction]` 与角色方向模板数据。
6. 只有所需方向全部存在时，角色母版节点才能通过并进入动作生成。
7. 页面刷新后从已持久化的逐方向 URL 重建同一宫格，不从东向母版推测其他方向。

现有“一方向一任务”的控制器结构继续作为唯一正式链路。本修复不切换到前端未使用的批量
方向集接口，也不把四向或八向压缩成一次 Provider 调用。

## Provider 提示合同

角色描述只表达身份、外观、服装、体型、气质和画风；方向数量与构图由宿主控制。Quick
Start Planner 生成的 `optimizedPrompt` 不加入多视图、转面表、精灵表或宫格构图要求。
即使用户手工输入这些词，后端仍在最终 Provider 提示中追加权威的单图输出合同：一个画布、
一个居中角色实例、一个完整身体、一个请求方向。

方向语义描述角色自身的朝向和可见身体表面，不改变摄像机位置、角度或项目投影：

- 东：右向侧面，脸、躯干、髋部和脚共同朝右。
- 西：左向侧面，脸、躯干、髋部和脚共同朝左。
- 北：角色背面朝向观察者，背部、后脑和腿后侧为主要可见表面。
- 南：角色正面朝向观察者，脸、胸腹和腿前侧为主要可见表面。
- 东北、西北：分别为右后、左后的三分之四朝向。
- 东南、西南：分别为右前、左前的三分之四朝向。

提示使用正向、可见结果导向的语句，避免依赖图片 Provider 不支持的 `negative_prompt`。

## 输出质量闸门

后端在抠图完成、上传开始之前复用现有 `subject_blobs` 读数检查每张候选：

- 读数为 1：允许上传和完成任务。
- 读数为 0 或大于 1：该任务失败，不上传错误图片，也不允许把它确认为母版。

该闸门能确定性阻止截图中的四主体拼图进入资产链路。它不假装具备视觉方向分类能力；方向
正确性由逐方向提示合同、独立任务合同和真实 Provider 验收共同保证。若 Provider 仍生成错误
朝向，用户使用现有“重做该方向”能力，只重试失败或不满意的方向。系统不自动追加付费调用。

## 前端状态展示

Quick Start 与 Workflow Editor 使用同一组持久化方向数据：

- 方向生成中：已完成方向显示独立图片，未完成方向显示带方向名称的生成中状态。
- 方向待确认：宫格中的每一格仍对应自己的候选 URL。
- 方向已确认：继续渲染完整四宫格或九宫格，不再退回只显示 `selectedImageUrl`。
- 单向已确认：继续显示现有单图卡片。
- 历史任务只有东向数据时按历史单向资产显示，不伪造其余方向；历史拼图需要用户重新生成，
  不做自动裁切或数据迁移。

## 错误与恢复

- 某个方向生成失败时保留其他已完成方向，只开放该方向重试。
- 质量闸门失败使用明确错误信息说明“一张方向图中检测到零个或多个主体”。
- 页面刷新、SSE 重连与任务恢复继续使用现有任务 ID 和方向字段，不增加临时前端状态作为
  权威数据。
- 全部方向未完成前，不自动开始动作首帧或完整动作生成。

## 实施范围

预计只修改以下现有边界：

- `backend/packages/common/src/windup_common/directions.py`：明确八个方向的角色朝向语义。
- `backend/packages/app/src/windup_app/server/orchestrator/executor.py`：单图输出合同与上传前主体数闸门。
- `frontend/src/features/quick-start-agent/planner.ts`：限制角色母版提案只描述单角色身份。
- `frontend/src/pages/quick-start/index.tsx`：四宫格、九宫格及确认后完整方向集合展示。
- `frontend/src/pages/workflow-editor/index.tsx`：确认后继续展示完整方向集合。
- 对应前后端测试文件。

不新增后端接口，不改变导出包格式，不修改积分规则，不引入图片裁切器、视觉分类模型或新的
自动付费重试机制。

## 验收标准

1. 四向流程产生四个独立任务结果和四个独立媒体 URL，页面以四个 `<img>` 组成 2×2 宫格。
2. 八向流程产生八个独立任务结果和八个独立媒体 URL，页面以八个 `<img>` 组成中心留空的
   3×3 九宫格。
3. 包含四个明显独立主体的合成图片在上传前被拒绝，不能进入角色资产或动作生成。
4. 八个方向的 Provider 提示具有互不相同且明确的身体朝向语义，同时保持项目摄像机和投影。
5. Quick Start 与 Workflow Editor 在生成中、待确认、已确认和刷新恢复后展示一致。
6. 单向项目与单向旧资产兼容行为不变。
7. 定向前后端测试、类型检查、格式检查及受影响的现有测试全部通过。
